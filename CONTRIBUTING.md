# Contributing to SourceHive 🐝

Thanks for helping build the hive! Every contribution counts: code, docs, design, bug reports, event ideas and feedback.

## Ground rules

- Be kind and respectful. Everyone taking part must follow our [Code of Conduct](CODE_OF_CONDUCT.md).
- Keep discussions in the open (issues, pull requests or [Discussions](https://github.com/orgs/sourcehive-org/discussions)) so others can learn from them.
- Never post secrets, passwords or personal data in issues or commits.

## How to contribute

1. **Find something to work on.** Look for issues labelled `good first issue` or `help wanted`, or open a new issue to suggest an idea.
2. **Say you're on it.** Comment on the issue so nobody else does the same work.
3. **Fork and branch.** Fork the repo and create a branch with a short, descriptive name, e.g. `fix/typo-in-readme` or `feat/registration-form`.
4. **Make your change.** Keep pull requests small and focused. Follow the existing style of the project and update the docs if behaviour changes.
5. **Commit clearly.** Write commit messages in the imperative mood, e.g. `Add hackathon schedule page`.
6. **Open a pull request.** Fill in the template, link the issue (`Closes #123`) and add screenshots for UI changes.
7. **Review.** A maintainer will review your PR. Please respond to feedback, since we're all learning together.

## Reporting bugs and requesting features

Use the issue templates in each repository. Please search existing issues first to avoid duplicates.

## Security issues

Please **don't** open public issues for security vulnerabilities. See [SECURITY.md](SECURITY.md).

## Questions?

Ask in [GitHub Discussions](https://github.com/orgs/sourcehive-org/discussions) or reach us through [sourcehive.org](https://www.sourcehive.org).

Happy building! 💛
